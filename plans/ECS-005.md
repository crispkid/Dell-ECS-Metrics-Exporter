# ECS-005 Execution Plan

## Purpose and Observable Outcome

Deploy ECS CE 3.8.0.3 in an isolated ESXi sandbox, run the real Exporter against its
Management API, correct observed schema/collection differences and record a redacted evidence
boundary. The observable outcome is a live smoke test that selects `ecs-3.8.0`, serves
authenticated Inventory and Prometheus data, and reports unavailable CE-only dependencies
without discarding usable Management data.

This change does not certify the entire ECS 3.8.0 range or the production ECS 3.8.1.4
environment.

## Context and Constraints

- Governing contracts: `SPECIFICATION.md` REQ-001–REQ-012,
  `DELL_ECS_API_MAPPING.md`, `docs/ecs-api/`, `TEST_PLAN.md`.
- Sandbox is ECS Community Edition, not a production appliance. Dell documents that CE lacks
  the production fabric layer and cannot validate failure scenarios.
- Only a least-privilege `SYSTEM_MONITOR` account and cleanable empty Namespace are used.
- Private endpoints, credentials, tokens, node identifiers and raw responses must not enter
  the repository.
- `tested_builds` and `sandbox_certified` remain unchanged until every certification
  prerequisite is satisfied.

## Surprises and Discoveries

- ECS 3.8.0.3 returned capacity and Namespace quota fields at the top level, while the inherited
  fixtures used nested envelopes.
- Node health used HAL-style `_embedded._instances`, not `node` or `nodes`.
- Bucket listing required a Namespace query parameter; a global list returned HTTP 400.
- The CE environment returned HTTP 503/code 6503 for every Flux query and contained no
  separate Flux/Influx backend container or executable.
- The 24 GiB minimum-style VM configuration used swap during bootstrap but completed without
  OOM or container restart. Dell's recommended long-running functional-test configuration is
  64 GiB.

## Decision Log

- 2026-07-25 — Preserve both inherited and observed envelope variants, and reject a response
  that contains both to avoid ambiguous source selection. Accountable role: Project
  Maintainer; no named reviewer recorded.
- 2026-07-25 — Enumerate Namespaces before Bucket pages because the live API rejects a global
  Bucket list. Retain bounded page/marker/duplicate checks per Namespace.
- 2026-07-25 — Separate Node Management from Node Resources. A Flux outage produces
  `DEGRADED` and explicit API/collector errors while retaining Node inventory/health.
- 2026-07-25 — Treat Flux 503 as a CE environment limitation for this evidence record, not as
  production API compatibility evidence and not as justification to weaken the 3.8.0 Profile.
- 2026-07-25 — Keep `tested_builds=[]` and `sandbox_certified=false`.

## Implementation Plan

1. Add alternate live envelope decoding with ambiguity guards in `internal/ecs/parser.go`.
2. Scope Bucket pagination by enumerated Namespace in `internal/collector/runner.go`.
3. Split Node Resources into an independent scheduled collector and preserve prior resource
   fields during Management refresh.
4. Add regression and race tests for live envelopes, cross-Namespace rejection and partial
   Node-resource failure.
5. Update common mapping, version mapping, test matrix, traceability and redacted evidence.
6. Run the full deterministic handoff gate and review the final repository for secrets.

## Verification Plan

- Narrow regression: `go test -race -timeout=3m ./internal/ecs ./internal/collector ./internal/health`.
- Full tests and coverage: Harness required stages with coverage at least 80%.
- Live smoke:
  - login/whoami/logout HTTP 200;
  - exact four-part-plus-build version selects `ecs-3.8.0`;
  - Host accepted/rejected behavior matches the 3.8.0 contract;
  - Management collectors and five Inventory endpoints return valid data/envelopes;
  - Prometheus self/domain families render and unsupported Bucket performance is absent;
  - CE Flux 503 is visible as `DEGRADED`, not hidden or converted to invented values.
- Security: raw responses remain in ignored `0600` temporary storage; repository secret scan
  and `govulncheck` pass.

## Recovery and Idempotence

- OVA import, step1 and step2 are not rerun after successful initialization.
- The added Namespace is empty and can be removed with ECS configuration tooling if no longer
  needed.
- Parser and collector changes are backward compatible with existing nested fixtures.
- Failed collection retains the last complete cache snapshot; restart rebuilds the in-memory
  cache and logs out the ECS token on shutdown.
- The ECS VM remains powered on for future tests; no production system or data is touched.
