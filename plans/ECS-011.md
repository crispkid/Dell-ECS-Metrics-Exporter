# ECS-011 Cross-Version Shared Feature Validation

## Purpose and Observable Outcome

Adopt the user's validation rule that a function proven on any one target ECS version is treated
as validated for all four target Profiles. The outcome is one machine-readable shared capability
list, consistent version documents, and release policy that checks shared functional evidence
without inventing exact-build execution records.

## Decision

- Policy value: `shared-live-any-target-version`.
- Qualifying evidence is a real ECS CE or appliance run through the Exporter production path.
- A validated shared function applies to ECS 3.6, 3.7, 3.8.0 and 3.8.1.
- Known version differences and `unavailable` capabilities remain Profile-specific.
- `tested_builds` and `sandbox_certified` remain exact-build/full-Profile facts and are not
  populated by inheritance.

## Shared Validated Scope

Authentication, version discovery, Cluster health/capacity, Node inventory/health,
CPU/Memory/Network latest snapshots, Namespace/Bucket inventory/capacity/quota/billing,
supported VDC/Namespace performance, Inventory API, Prometheus/readiness and explicit TLS
verification disable are validated shared functions.

Node service/process, Disk, Flux interval rates, replication status/lag and recovery progress
remain pending because no target version has qualifying live evidence. Bucket performance remains
unavailable by design.
