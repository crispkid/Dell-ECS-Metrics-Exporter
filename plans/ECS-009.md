# ECS-009 Execution Plan

## Purpose and Observable Outcome

Correct the Exporter's ECS 3.8.1.x Flux mappings using Dell documentation and
authorized read-only evidence from an exact 3.8.1.1 appliance. The observable
outcome is a runtime that exports real Node CPU, Memory and Network values,
maps only proven VDC/Namespace performance series, permits an explicit
self-signed-certificate TLS exception, and preserves atomic cache behavior.

## Context and Constraints

- Exact observed build: `3.8.1.1.140118.8d698782e5d`; the endpoint, credentials,

  management IP. The user explicitly permits `tls.verify: false`.
- Dell Flux on this build supports the query operations used here:

- Partial live evidence does not populate Profile `tested_builds`, set

- Existing unrelated README, PROJECT, deploy-check and local deployment changes
  must be preserved.

## Decision Log

- TLS verification remains enabled by default. Explicit `false` is accepted in
  every environment and emits a warning containing only cluster/environment.
- CPU, Memory, Network and conditional Disk are separate requests. Any failed
  request prevents the entire Node resource cache replacement.
- VDC core and latency plus Namespace requests are separate requests. Broad
  `cq_performance_.*` queries are prohibited.
- `ttfb_read` maps to READ and `ttlb_write` maps to WRITE; p50/p99 values are
  converted from milliseconds to seconds.
- Transaction success maps to 2xx, user errors to 4xx and system errors to 5xx.
  Aggregate failed transactions are omitted to prevent misclassification and
  double counting.
- Namespace throughput and latency were synthetic assumptions without official
  or appliance evidence and are removed from the public metric contract.

token expiry/reauthentication, range-boundary behavior, failure injection,
non-zero workload performance, multi-VDC replication/recovery, least-privilege
account validation and named review remain required for formal certification.

network-receive and ten network-transmit series, and 32 current metric families

or Namespace rows, so non-zero workload behavior remains explicitly pending.
The full Harness stopped at its required security stage because `vuln.go.dev`
could not be resolved; no security pass is claimed for the current change.
