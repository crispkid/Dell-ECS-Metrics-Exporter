# ECS-004 Execution Plan

## Purpose and Observable Outcome

完成 Dell ECS Metrics Exporter 的 mock-verified V1 runtime。Operator 可用 strict
YAML/secret files 啟動程序，從一或多個 ECS Cluster 排程收集資料，透過
Prometheus `/metrics` 與 authenticated `/api/v1` 讀取原子快取，並以 Docker/Helm
部署。Repository handoff 以全部 required Harness stages 通過為準。

真實 ECS 相容認證不在此 plan 假設完成；使用者會另行安排環境。任何 Profile 在
live evidence 前都維持 `tested_builds=[]`、`sandbox_certified=false`。

## Surprises and Discoveries

- Local sandbox forbids opening TCP listeners. Client component tests therefore use an
  in-memory `http.RoundTripper` while still exercising `http.Client`, redirects, headers,
  token lifecycle and retry. This remains mock evidence, not live network evidence。
- The first sandboxed `verify` could not resolve `vuln.go.dev`; the required security
  stage passed after explicitly authorized access to the official Go vulnerability database,
  and the final evidence report records every required stage as passed。
- RG link fixture contains both a completed failover field and active bootstrap field;
  its manifest expects bootstrap progress. Parser therefore preserves the explicit active
  bootstrap kind instead of collapsing both recovery processes。
- Mapping has no verified replication list endpoint. Runtime requires configured group/link
  IDs and does not invent discovery URI。
- Bucket list pagination evidence is candidate-level. Runtime supports bounded
  `marker`/`next_marker`, duplicate and loop rejection, but live parameter/schema still
  requires certification。

## Implementation Plan

1. Parse and validate YAML defaults/overrides, files, TLS, security, intervals and timeouts。
2. Resolve per-cluster credentials and build isolated HTTPS/auth/retry clients。
3. Bootstrap `/vdc/nodes`, select Profile intersection and verify `/user/whoami`。
4. Poll each domain into validated models and only replace cache after full success。
5. Render cached domain/self metrics and authenticated inventory with bounded queries。
6. Wire scheduler, graceful HTTP shutdown/logout and structured runtime observers。
7. Package with scratch image, external config/Secret Helm mounts and read-only CI。
8. Verify contracts and synchronize governance/documents。

## Recovery and Idempotence

- Config/profile validation is read-only and repeatable。
- Collector failures retain the last complete snapshot; restart rebuilds memory cache。
- Token is invalidated on first 401 and logout clears it even on response failure。
- Helm upgrade can roll back to a previously verified digest; config and Secret are external。
- This change creates no ECS resources and has no remote cleanup obligation。

deployment chart and read-only CI contract. `./HARNESS/harness.sh verify` passed lint、format、
typecheck、test、coverage、build、security、deploy and ci-policy; coverage is 86.1% and the
