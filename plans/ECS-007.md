# ECS-007 Execution Plan

## Purpose and Observable Outcome

修正 ECS CE 3.8.0.3 非空 Bucket 實測揭露的相容性問題。完成後，Exporter 會同時
接受既有 nested 與 ECS 3.8.0.3 top-level Bucket quota／單筆 billing response，
拒絕同時出現兩種 envelope 的模糊 response，並依確認後的 BucketListParam schema
送出 batch billing JSON `{"id":[bucket names...]}`。Billing response 的 `KB`
依已知大小物件實測使用 1024 bytes；其他單位與 capacity/quota GB 不因單一觀察
而改變。

## Context and Constraints

- Governing contracts: `SPECIFICATION.md` REQ-004、REQ-009、REQ-012、
  `DELL_ECS_API_MAPPING.md`、`docs/ecs-api/common-contract.md`。
- Exact live build: ECS CE `3.8.0.3.138685.3a0a9b6bf3a`。
- Live dataset: three test Buckets and four objects totaling 10,000,000 bytes。
- Nested response support must remain backward compatible.
- A JSON `null` body produced HTTP 500/code999, so that pair does not prove the endpoint is
  unsupported and does not authorize fallback. Only 404/405/501 or a missing requested item
  falls back to single-bucket billing.
- Error-code parsing may retain the normalized numeric code in memory but must not log or
  preserve the raw error response.
- `9765.625 KB` for 10,000,000 bytes proves only the billing `KB` multiplier of 1024.
  Existing decimal MB/GB/TB and capacity/quota GB mappings remain unchanged until separately
  proven.
- `tested_builds=[]` and `sandbox_certified=false` remain unchanged. A corrected component
  test is not a corrected live run.

## Decision Log

- 2026-07-26 — Bucket quota and single billing accept either the inherited nested envelope or
  the ECS 3.8.0 top-level fields. Responses containing both are rejected as ambiguous.
- 2026-07-26 — The earlier proposal to treat HTTP 500/code999 as an unsupported batch endpoint
  is superseded. Live evidence shows this result was caused by JSON `null`; only
  404/405/501 or a missing requested item authorizes fallback.
- 2026-07-26 — ECS 3.8.0.3 batch request uses `{"id":[bucket names...]}` and the response
  envelope is plural `bucket_billing_infos`.
- 2026-07-26 — Billing `KB` uses 1024 bytes. MB/GB/TB and capacity/quota GB retain the existing
  decimal contract because this run did not prove their multiplier.
- 2026-07-26 — The exact live build remains partially verified and is not promoted to a tested
  or sandbox-certified Profile.

## Verification Plan

- Parser tests for nested and top-level Bucket quota/single billing, missing envelopes and
  ambiguous dual envelopes.
- Client tests for numeric and numeric-string ECS error code extraction without exposing the
  raw error body.
- Batch request tests for required JSON entity/object encoding, the confirmed plural success
  envelope and the observed 415/400/code1013/500/code999 classifications.
- Collector tests cover 404/405/501 and missing-item fallback plus generic 500 and
  500/code999 no-fallback behavior.
- Known-size assertion:
  `6835.9375 KB + 2929.6875 KB + 0 KB = 9765.625 KB`,
  and `9765.625 × 1024 = 10,000,000 bytes`.
- `go test -race -timeout=3m ./...` and `./HARNESS/harness.sh verify`.
- The corrected live rerun verified three Bucket inventory items, four objects,
  10,000,000 used bytes, configured/unset quota semantics, Cluster/Namespace aggregates and
  HTTP 200 `DEGRADED` readiness whose only collector error was the known CE Flux 503.
